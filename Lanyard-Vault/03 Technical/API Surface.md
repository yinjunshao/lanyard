# API Surface

Grouped from route definitions in `worker/*.js`. All under `/api` unless noted.

**Session and account:** `GET /me`, `POST /logout`, `POST /terms/accept`, `GET /account/export`, `DELETE /account`, `POST /account/email`, `/account/email/confirm`, `/account/event-emails`, `/account/marketing`, `GET /auth/sessions` (each device has an opaque `id`), `POST /auth/signout-others`, `DELETE /auth/sessions/:id` (one of your own other devices; someone else's or a made-up id is 404, this device is 400)

**Sign-in:** passkey register/login (`/passkey/...`), email (`/auth/email/start`, `/verify`), TOTP (`/auth/totp/setup`, `/confirm`, `/redeem`, `DELETE`), recovery (`/auth/recovery`, `/recovery/redeem`), `POST /auth/redeem`, `/auth/link`

**Profile and cards:** `PUT /onboarding` (F14: `{ step: 1 to 6 }` moves a person in the welcome steps, `{ done: true }` finishes; anything else is 400, no profile is 404, and for anyone not in the steps it changes nothing and counts nothing), `GET/POST/PUT /profile` (`POST` with `onboarding: true` starts the welcome steps at step 2; it still needs `acceptTerms` and `over18`; `mode` must be `student` or `career`, otherwise 400; `company` and `role` are trimmed to 80 characters; `institutionId` (or `institution_id`) must be an id from the institution list or null, otherwise 400, and a listed id sets `uni` to the official name; typed `uni` text is capped at 120 characters and, when it changes without an id, clears `institution_id`. `GET /me` also returns `user.emailDomain` for the institution suggestion. `GET /c/:cardId`, `GET /connections`, `GET /connections/:id` and `GET /e/:id/room` return `mode`, `company` and `role` alongside `uni`, `course` and `year`), `POST /cards`, `PUT/DELETE /cards/:id`, `POST /cards/:id/rotate-code`, personal-note routes, `GET /c/:cardId`, `GET /code/:code`

**Event presence (F17, `worker/presenceApp.js`):** all need a signed-in person checked in to the event. `GET /e/:id/presence` your own state (`available`, `why`, `on`, `intro`, `lookingFor`, `selfie`). `PUT /e/:id/presence` turns it on or changes it (`consent: true` first time and with every selfie, `intro`, `lookingFor`, `selfieDataUrl` or `null`); 403 unless the event is ongoing and its directory is on; 30 changes an hour and 10 selfies a day (429). `DELETE /e/:id/presence` withdraws (allowed after the event ends). `GET /e/:id/suggestions` (needs presence on yourself; 120 an hour) returns `{ mode, topics, people: [{ presenceId, name, selfie, intro, reason }] }` and nothing else. `POST /e/:id/presence/:presenceId/report` `{ reason?, block? }`. `/media/presence/...` serves a selfie only to people allowed to see it, `no-store`. The data export has `eventPresence`; host live and report have `presenceUsed` / `totals.presence` (a count, hidden under 3).

**Shared ground (F16):** `GET /c/:cardId` (signed-in viewers who are not the owner) and `GET /connections/:id` also return `inCommon: [{ kind, text }]`, at most 3, kinds `tags`, `course`, `company`, `event`, `institution`, worked out per request and never stored ([[D026 Shared ground is worked out from what each person shows, and never stored]]). Empty for signed-out viewers, your own card, a blocked pair and when nothing matches. `GET /connections` (the people list) does not return it. No host route reads it.

**Connections:** `POST /connect` (takes `via`: `qr`, `code` or `link`; anything else or nothing is stored as `link`; set only when the connection is first made), `GET /connections` (each has `via`, `eventName`, `metAt`), `GET /connections/:id` (same, and `eventName`), `GET /c/:cardId` (`viewer.connection` has `via`, `event`, `metAt`; `via` is `null` for connections made before F13) and the data export (`connections[].via`), `PUT /connections/:id/note`, `/meta`, `POST /connections/:id/report`, `DELETE /connections/:id`

**Events (attendee):** `GET /e/:code`, `POST /e/:code/checkin`, `GET /e/:id/room`, `/album`, `/feedback`, `POST /e/:id/feedback`, `GET /my/events` (F15: each event has `startsAt`, `endsAt`, `endedAt`, `status` of `upcoming`, `ongoing` or `ended` for that person, `checkedInAt`, `connectionCount`, and the server clock `now`), `GET /my/events/:id` (F15: the event, `status`, `checkedInAt`, `connectionCount`, `roomCount` (others in the room, `null` with the directory off), `connections` of the viewer's own at that event with `via`, `metAt`, `cardId` and a selfie only when the viewer may see it, and `event.hasChoices`; 404 unless checked in, 401 signed out; it lives in `worker/myevents.js`), `GET /home`

**Host** (host site only, host cookie only; refused on the main site and from other origins, see [[Auth and Sessions]]): `POST /host/auth/start`, `/host/auth/verify` (email code), `POST /host/logout`, `GET /host/me` (includes `step`: details, terms, org, ready), `POST /host/account/details`, `POST /host/terms`, `GET /host/sessions`, `DELETE /host/sessions/:id`, `POST /host/sessions/signout-others`, `GET /host/account/export`, `/host/org(s)`, `/host/events` (create, `PUT :id`, duplicate, end, rotate-code, live, report, report.csv, feedback; `live` also returns the host's own theme, brand colour, perks, directory setting, check-in questions and sponsors, for the Details preview, F18; the Present page and the poster, F19, read the same route and use only the event's own details and `checkins`), `/host/billing`, `/host/billing/request`, `/host/team` (invite with an optional email, join, remove by host account id), `/host/transfer(s)`, `/host/tickets`, `/host/terms`, `/host/integrations` (webhook, key)

**Host promo codes (F20, `worker/host-promo.js`, host site and host cookie only):** `GET /host/redeem/:code` (what the code gives, and your own organisation's claim; 30 lookups per 10 minutes per IP and per host account), `POST /host/redeem/:code` (claim for your own organisation; owner or staff; 20 a hour per host account, 30 an hour per IP; wrong codes 30 an hour per IP and per account). Every code that cannot be used (unknown, switched off, not started, ended, full, for another kind of organisation, an attendee code) is the same 404 `bad_code`. `POST` answers `{ promo, mine: { held, credits, ... }, org, credits: { remaining }, already? }`. The host data export has `promoCodes`; Billing has `heldPromos`. **Admin** (token): `GET /admin/promos` (both audiences; host codes carry `claims`, `held`, `credits_issued`), `POST /admin/promos` (`audience: host` with `credits`, `creditDays`, a required `maxUses`, `orgKinds`), `POST /admin/promos/:code/edit` (limit, dates, note), `POST /admin/promos/:code/active`; `POST /admin/orgs/:id/review` also returns `released` (held claims issued on approval).

**Integrations:** `POST /integrations/rsvp` (API key sets an event's RSVP count)

**Promo codes:** `GET /redeem/:code` (look up; 30 per 10 minutes per IP and per person, wrong codes 30 an hour per IP), `POST /redeem/:code` (claim; 20 an hour per person). See `worker/promo.js`.

**Admin onboarding** (token): `GET /admin/onboarding` (counts per step for the last 30 days: `steps[].step`, `reached`, `completed`; no ids).

**AI (F21, `worker/ai/routes.js`):** `GET /ai/status` (signed in: `{ on, searchOk, allowances: [{ key, label, free, plus }] }`; 401 signed out), `PUT /ai/search` `{ ok: true|false }` (the opt-out; 403 with no card, 400 for a non-boolean, 20 changes an hour). Features add `/api/ai/<feature>` and call `callModel`; none exists yet. The data export has an `ai` section (counts, replies still held, the search choice), and the host export has the host's own counts.

**AI follow-up drafts (F22, `worker/ai/followup.js`, signed in):** `GET /ai/followup/:connectionId` (what the composer offers: `talkAbout` (their tags on the card they shared with you, then the shared ground), `offer` (your own tags), `hasNote` (never the note), `themFirst`, `meFirst`, `eventName`, `allowance` `{ day, month }` or null, `limits`; 404 if it is not your connection or the pair is blocked). `POST /ai/followup/:connectionId` `{ channel: linkedin|email|whatsapp, tone: friendly|professional|short|enthusiastic, goal: stay_in_touch|advice|coffee|work_together|thanks, talkAbout[], offer[], useNote, extra, regenerate }` returns `{ fallback: false, draft: { subject?, body }, cached, allowance }` or `{ fallback: true, reason, message, allowance }` (a normal 200: the page shows its template); 400 for a bad choice, 404 for someone else's connection. `POST /ai/followup-count` `{ kind: copied|opened|marked }` (counts only; 120 an hour a person, then ignored). The admin AI response gains `followup` (five counts, today and this month).

**Named attendance (F31, [[D038 Named attendance is per event, shown on the check-in page and pre-ticked by the owner's choice]]):** `GET /api/host/events/:id/attendees` and `.csv` (host site and host cookie only, the event's own organisation; 404 with code `list_off` for an event without the list, 404 for another organisation's event, 401 signed out) list only the people on the list with only the extra items each left ticked. `POST /api/host/events`, `PUT /api/host/events/:id` and `POST /api/host/events/:id/duplicate` take `collect: { attendance, items, why }` (only `attendance: true` switches it on; items only `email` and `card`; why 10 to 200 characters; anything else is 400; a copy never inherits it); the host's `/live` carries `event.collect` only when it is on. Attendee side: `GET /api/e/:code` carries `event.collects` (organiser, why, items with their words) only when it is on; `POST /api/e/:code/checkin` takes `collect: { attendance, email, card }` (each must be `true` to count; a request with no `collect` changes nothing); `GET` and `PUT /api/e/:id/attendance` (the person's own standing and change of mind; whatever a PUT leaves out is false); `GET /api/account/attendance` (every list the person is on, for Settings); `GET /api/my/events/:id` gains `event.namedAttendance` only when it is on. `GET /account/export` gains `namedAttendance` and `GET /host/account/export` gains `attendeeLists`, each only when there is something to say.
**Drops (F32, [[D039 Drops are sealed with a Worker key, given by one conditional write, and vouchers are marked with a staff PIN]]):** attendee side, signed in and checked in (signed out 401, not checked in 403, another event's drop 404; the host site and the host cookie get nothing; no guest is made): `GET /api/e/:id/drops` (each drop's title, note and where it stands for the person; never an item), `POST /api/e/:id/drops/:did/reveal` ("Show": gives the item if none yet, then returns it; limited per drop and overall; `no-store`), `POST /api/e/:id/drops/:did/use` (a voucher, `{ pin }` typed by staff). A person's own items and voucher uses are in `GET /api/account/export` under `drops`. Host side (`worker/dropsHost.js`, host site and host cookie, the event's own organisation): `GET`/`POST /api/host/events/:id/drops` (counts; make a drop, 503 `drops_unavailable` when the server has no `DROP_KEY`), `PUT .../drops/:did` (title, note, window, stop or start), `POST .../items` (add more), `POST .../unused` (download the unused items as text: decrypted, 5 an hour, audited), `DELETE .../unused`, `DELETE .../drops/:did`, `POST .../pin` (a new voucher PIN, shown once), `GET .../people` and `POST .../revoke` (only for an event that keeps a named list, and only for people on it). The host's account download has `drops` (counts, never an item). **Withdraw and replace (F34):** `POST /api/host/events/:id/drops/:did/replace` `{ giveId }` (host site only, same event rules as revoke, 60 an hour per host): for one-each and random-without-reuse drops only (400 for the others), 404 for anyone not on the named list right now, 409 `none_left` (nothing changed), `changed` (just replaced), or the drop's own state (`stopped`, `not_yet`, `closed`). It never returns an item; the person sees the new one on their next Show, and their drop list and reveal carry `replacedAt`.


**AI feedback summary (F23, `worker/ai/feedbackSummary.js`, mounted in `worker/hosts.js`, host site and host cookie only, the event's own organisation):** `GET /host/events/:id/feedback/summary` returns `{ eligible, needed: 5, mostAnswered, written, summary: { paragraph, worked: [{ text, count }], change: [...], quotes: [{ text, question }], basedOn, createdAt, source, newer } | null, figures: { responses, rating: { label, average, answered } | null, again: { label, yes, answered, percent } | null } | null, allowance: { left, of } | null }`. `POST` on the same path writes (or rewrites) it and returns the same plus `fallback: { reason, message }` when AI is not available (a normal 200). Below 5 written answers to one question `eligible` is false and no model is called. 401 signed out, with an attendee cookie or on the main site; 404 for another organisation's event; 3 manual summaries a day per host, 1 call in 5 seconds. The hourly scheduled run also writes one when an event's feedback window has closed (`feedback_summary_auto`, no burst limit, not counted against the 3).

**AI people search (F24, `worker/ai/peopleSearch.js`, signed in):** `GET /ai/people-search` returns `{ allowance: { day, month } | null }` (null: this person cannot use AI search). `POST /ai/people-search` `{ query (3 to 200 characters, cleaned), regenerate? }` returns `{ fallback: false, matches: [{ connectionId, reason, matchedOn }], cached, allowance }` (up to 5, possibly none) or `{ fallback: true, reason, message, allowance }`; the page then ranks by keyword. 400 for a query that is not text, too short or has no letters. Nobody to search (no connections, or none who can be searched) is a normal empty list with no model call and nothing used up, and does not say why. Feature `people_search` in `AI_LIMITS`: 5 a day free, 30 Plus; burst and address limits as for every AI call. No user id, card id, name or email is in the answer. Not on the host site.

**AI who to meet (F25, `worker/ai/whoToMeet.js`, signed in, checked in to the event):** `GET /ai/who-to-meet/:eventId` returns `{ allowance: { left } | null }` (rankings left for this event). `POST /ai/who-to-meet/:eventId` takes no body (the wish is the one saved with presence; anything sent is ignored) and returns `{ fallback: false, improved, people: [{ presenceId, name, selfie, intro, reason }], cached, allowance }` (the same entry shape as `GET /e/:id/suggestions`, at most 5) or `{ fallback: true, reason, message, allowance }` (the page keeps F17's list; `no_wish` when no wish is saved). The gate is F17's: not checked in 403, directory off 403, event not on 403, presence off 403 `presence_off`, a refused request is made before the cache is read. Limit: 3 per event on Free, 10 on Plus (`who_to_meet` in `AI_LIMITS`, scope = the event); 60 requests an hour per person.

**Admin AI** (token, `worker/ai/admin.js`, registered on `adminApp`): `GET /admin/ai` (state, whether the key and gateway are set (never their values), prices and whether confirmed, spend against both budgets, calls, cache hit rate, fallbacks, per feature, top 10 ids, people at a limit 3 days running), `POST /admin/ai/kill` `{ killed }`, `POST /admin/ai/rollout` `{ mode }`, `PUT /admin/ai/allow` `{ emails }` (up to 50), `POST /admin/ai/test` (one tiny call with no personal data).


**Admin hosts** (token): `GET /admin/hosts?q=` (host accounts and organisations with no host), `POST /admin/hosts/:id/status`, `POST /admin/orgs/:id/attach` (by host email)

**Pages and crawler files (F37, [[D042 A shared card link shows what the card already shows, and is never indexed]]):** not `/api` routes, answered by `worker/seo.js` for any path no other route took. `GET /robots.txt` (main site: `Allow: /`, `Disallow` for `/api/`, `/app`, `/admin`, `/signin`, `/claim`, `/redeem`, the sitemap link; `/c/` and `/e/` are deliberately not disallowed; host site: `Disallow: /`), `GET /sitemap.xml` (`/`, `/hosts`, `/terms`, `/privacy`; 404 on the host site). `GET /`, `/hosts`, `/terms`, `/privacy`, `/privacy-request`, `/c/:cardId` and `/e/:code` return the app shell with its tags rewritten; every other path returns the shell untouched. `X-Robots-Tag: noindex, nofollow` on every response except `/`, `/hosts`, `/terms`, `/privacy`, `/robots.txt` and `/sitemap.xml` of the main site. `/e/:code` shares the `code:ev:<ip>` wrong-code counter with `GET /api/e/:code`.

**Error wording (F39, [[D044 Errors say what happened and what to do, and the vague ones stay vague]]):** every `{ error, code }` carries plain words for a person (the `code` never changes); a 429 may carry `retryAfter` (seconds) or a `Retry-After` header, which the browser turns into the wait. The words are checked by `test/errors.mjs`.

**Card payments (F36, [[D041 Polar as merchant of record behind one provider module]]); every write is 503 `billing_off` "Card payments are not switched on yet." unless `BILLING_ENABLED = "1"` (production sets nothing):** `GET /billing/plans` (works when off: `cardPayments`, `seller` only when on, the Plus products with our prices, `includes` from `PLUS_INCLUDES`, `freeCards`; F41: signed in, it also has `mine` = `{ tier, until, renews, cancelAtPeriodEnd, interval, managed }` read from this user's own rows only, so it works with billing off. `until` is `users.plan_until` as an ISO date or null; `renews` is true only with an active or trialing subscription not set to end; `managed` is true with a paid or refunded order, which is what `POST /billing/portal` accepts; signed out has no `mine` and still makes no guest). `POST /billing/checkout` `{ product: "plus_month" | "plus_year", startNow: true }` → 201 `{ url }` (Polar's hosted page); signed out 401 (never makes a guest); a card with no way to sign in 403 `needs_signin`; anything else as `product` 400 `unknown_product`; any `quantity` but 1 400 `bad_quantity`; no tick 400 `express_start`; already Plus 409 `already_plus`; 10 an hour per person (429); Polar unreachable 502 `provider_error`; any price, amount or currency sent is ignored. `POST /billing/portal` → `{ url }` of Polar's Customer Portal (404 `no_billing` with nothing bought; 20 an hour). `POST /webhooks/polar`: Standard Webhooks signature over the raw body, 5 minutes, several signatures; 400 `bad_signature`; 413 over 256 KB; outside the session and same-origin middleware; 200 `{ ok, outcome }` (granted, recorded, plus, ended, refunded, part_refunded, mismatch, no_order, renewal, already, ignored, duplicate). Host site: `POST /host/billing/checkout` `{ product: <a HOST_SKUS pack of the organisation's own prices>, startNow: true }` with the same refusals (403 while pending approval, 10 an hour per organisation); `GET /host/billing` adds `cardPayments`, `seller` and `card` on each pack. No route takes a refund or confirms a payment from the browser. Data downloads add `billingOrders` (attendee) and `cardOrders` (host) only for someone who started a card payment.

**Limits and refusals added by the F35 audit** ([[Security Audit 2026-11-15]], [[D040 Limits and claims are enforced in the write itself, and a guess is counted before it is checked]]): `GET /e/:code` and `POST /e/:code/checkin` answer 429 `throttled` after 30 wrong event codes in 10 minutes from one IP (right codes are not counted). `POST /host/events` and `/duplicate` answer 402 `no_credits` whenever the credit (or the society's free week) was taken by a request at the same moment. `POST /cards` answers 402 `plan_limit` likewise. `POST /host/team/join` answers 404 when the invite was used a moment before. `POST /host/team/invite` with an email: 10 a day per organisation, 3 a day per address; `POST /host/transfer`: 5 a day per organisation, 3 a day per account; over is 429 `throttled`. `POST /privacy-request` always records the request; one address gets at most 3 acknowledgement emails a day (`acknowledged: false` after that). `POST /host/billing/request` `quantity` is a whole number 1 to 20 or left out (400 `bad_quantity`); `rsvpCount` on event create and edit is empty or a whole number 0 to 100,000 (400 `bad_rsvp`); a feedback rating is a whole number 1 to 5 (400 `bad_rating`, nothing stored); `PUT /cards/:id` `theme` is one of default, formal, night, host (400). `POST`/`PUT /profile` with a new photo: 20 an hour (429). Signed-out `GET /code/:code` lookups are counted per IP only.

**Other:** `GET /health`, `GET /media/:key`, `/admin` routes (token), `POST /plan/waitlist`. Not under `/api`: `GET /host` and `/host/*` answer 301 to the same page on the host site (F10)
